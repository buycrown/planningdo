    경로는 site-config.js (window.LFSite) 한 곳만 소유합니다.

   ★ 사내망 차단·오프라인 등으로 로드에 실패해도 ADMIN 의 기존 기능은 모두 정상 동작합니다.
     이 경우 엑셀 관련 버튼만 비활성화되고 각 화면에 노란색 안내 문구가 표시됩니다.

■ v2.0 변경 사항
────────────────────────────────────────────────
1) 수수료 관리
   - 신청 내역 테이블에 [수수료율] 컬럼 추가 (미설정이면 '-', 값이 있으면 '5%')
   - 각 행 맨 앞 체크박스 + 헤더 전체선택(현재 페이지 기준, 선택 상태는 id 기준으로 유지)
   - 1건 이상 선택 시 상단에 일괄 작업 툴바 노출
     → [💰 수수료 일괄 입력] : setCommission API
     → [🔗 링크 일괄 배포]   : linkBulkCreate API
   - 상세 모달에 [수수료율(%)] 입력 필드 추가 (update API 의 commissionRate)

2) 링크 관리 (좌측 네비 '🔗 링크 관리')
   - 인플루언서 선택(검색 가능) + '전체 보기'
   - 목록: 인플루언서 / 링크명 / URL / 등록일 / 유효기간 / 상태 / 관리
   - 상태 뱃지: 활성(초록) · 예정(파랑) · 종료(회색)  ※ 서버가 유효기간으로 자동 계산
   - URL 새 창 열기 + 📋 복사 버튼
   - [+ 링크 추가] / [수정] / [삭제] → linkCreate / linkUpdate / linkDelete
   - 유효종료일을 비우면 '무기한' 활성 링크
   - 상단 통계 타일: 전체 링크 / 활성 / 종료

3) 수익 관리 (좌측 네비 '💰 수익 관리')
   - 연월 선택기(기본값 = 이번 달) + [조회]
   - 그리드: 인플루언서 / 활동명 / 수수료율 / 해당 월 수익(입력) / 누적 총수익 / 저장
   - 금액 입력은 숫자만 허용하며 입력 중 3자리 콤마가 표시됩니다.
   - 값이 변경된 행은 노란색 배경 + 좌측 컬러 바로 표시됩니다.
   - 행 단위 [저장] / 상단 [💾 변경분 일괄 저장](진행률 표시) → revenueUpsert API
   - 하단 요약: 해당 월 총 지급액 / 입력 완료 인원 / 미입력 인원

4) 회원 로그인 비밀번호 변경
   - 상세 모달 하단 [🔑 로그인 비밀번호] 섹션
   - 현재 상태(설정됨/미설정 + 최종 변경일시) 표시, 목록에도 [비밀번호] 상태 컬럼 추가
   - 새 비밀번호 / 확인 + 표시 토글 + 강도 인디케이터(LFAuth.validatePassword 실시간 검증)
   - [비밀번호 변경] → LFAuth.makeCredential(pw) → adminSetPassword API
   - ★ 평문 비밀번호는 절대 서버로 전송하지 않습니다.
     브라우저에서 PBKDF2-SHA256(120,000회)로 파생한 값만 전송합니다.
   - WebCrypto 사용 불가(비보안 컨텍스트) 환경에서는 섹션이 비활성화되고 안내 배너가 뜹니다.

5) LFmall ID 강등 (Legacy)
   - 상세 모달 라벨: 'LFmall ID (Legacy)' + readonly + 회색 처리
   - [+ 신청 추가] 모달에서는 LFmall ID 입력란을 노출하지 않습니다. (v2.0부터 미수집)
   - 목록 컬럼과 검색 옵션은 기존 데이터 확인을 위해 유지합니다.

■ v2.1 변경 사항
────────────────────────────────────────────────
6) SNS 채널 — 유형별 컬럼 반영 (서버 신청내역 21~26열)
   - list 응답의 `snsByType`{instagram/youtube/x/tiktok/etc} 과 `primaryChannelType` 을
     **우선** 사용합니다. 비어 있으면 기존 `snsText` 를 parseSns() 로 파싱해 폴백하므로
     v2.1 이전에 등록된 데이터도 화면이 비지 않습니다.
   - 신청 내역 목록에 [대표채널] 컬럼을 추가했습니다. (아이콘 + 유형명)
   - 상세 모달에 유형별 SNS 목록(읽기 전용)을 추가했습니다.
     아래 [SNS 채널 원본] textarea 는 그대로 편집용으로 유지되며,
     저장하면 서버가 원본을 유형별 컬럼으로 자동 재분류합니다.
   - 유형별 입력이 필요하면 update 에 snsChannels:[{channel,url}] 을 보내면 됩니다.

7) 순번 PK 노출 (UUID → "1","2"… 문자열)
   - 링크 관리에 [링크번호], 수익 관리에 [수익번호], 초대 내역에 [초대번호] 컬럼 추가
   - 타입은 계속 문자열이므로 기존 비교 로직(l.id === createdId)은 그대로 성립합니다.
   - id 를 UUID 정규식으로 검증하는 코드는 없습니다. (회원 PK 만 UUID 유지)

8) 엑셀 기능 (SheetJS)
   8-1) 조회 결과 엑셀 다운로드 — 4개 화면 전부 [⬇ 엑셀 다운로드]
        - 신청 내역 / 초대 내역 / 링크 관리 / 수익 관리
        - **현재 화면에 조회된 결과 기준**입니다. 검색어·필터가 적용된 상태 그대로이며,
          페이징과 무관하게 조회된 전체 행이 들어갑니다.
        - 파일명 : LFmall_신청내역_20260804.xlsx  (화면명 + 날짜)
        - 헤더 행 굵게·배경색, 열 너비 자동, 틀 고정(1행), 자동 필터
        - ★ 개인정보 보호
          · 파일에는 **현재 마스킹 상태가 그대로** 반영됩니다.
          · 마스킹을 해제한 상태에서 내려받으면 실제 이름·이메일·휴대폰이 파일로 나갑니다.
            이때는 다운로드 전에 확인 모달이 뜨고, 완료 후 화면 상단에
            '개인정보가 포함된 파일입니다. 취급에 주의해 주세요.' 안내가 표시됩니다.
   8-2) 양식 다운로드 — 링크 관리 / 수익 관리 [📄 양식 다운로드]
        - 링크_대량등록_양식.xlsx
            시트1 링크등록 : 활동명 | 이메일 | 링크명 | 링크URL | 유효시작일 | 유효종료일 | 메모
            시트2 작성안내 : 항목별 설명 / 날짜 형식(YYYY-MM-DD) / 유효종료일 공백 = 무기한
            시트3 인플루언서목록 : 활동명 | 이름 | 이메일 | 수수료율(%)  (복사용)
        - 월별수익_대량등록_양식.xlsx
            시트1 수익등록 : 활동명 | 이메일 | 연월(YYYY-MM) | 수익금액
            시트2 작성안내 / 시트3 인플루언서목록
        - 예시 행 2줄이 들어 있으며 '(예시)' 가 포함된 행은 업로드 시 자동 제외됩니다.
        - ★ 개인정보 최소화 (4차 QA 조치)
          · 이메일 : 업로드 식별키라 원본이 필요합니다. → 그래서 양식 다운로드도
            **항상 확인 모달을 거칩니다.** (마스킹 ON/OFF 와 무관)
          · 이름   : 화면과 동일하게 현재 마스킹 규칙을 따릅니다.
            (마스킹 ON 이면 양식에도 '최*석' 으로 들어갑니다)
          · 휴대폰 : 업로드 식별에 전혀 쓰이지 않으므로 **아예 넣지 않습니다.**
          · 다운로드 후 화면 상단에 개인정보 취급 주의 안내가 표시됩니다.
   8-3) 엑셀 대량 업로드 — 링크 관리 / 수익 관리 [📥 엑셀 대량 업로드]
        - .xlsx / .xls / .csv 지원, 파일의 첫 번째 시트를 읽습니다.
        - 열 순서가 달라도 **헤더 이름**으로 찾습니다. 빈 행은 자동으로 건너뜁니다.
        - 파싱 후 **미리보기 표**에서 행별로 정상 / 오류(사유) 를 색상과 함께 보여주고,
          사용자가 확인한 뒤에만 실행됩니다.
        - 검증 항목
            · 인플루언서 식별 : **활동명 또는 이메일 중 하나**로 찾습니다.
              둘 다 있으면 이메일 우선, 둘 다 없거나 활동명이 중복되면 오류
            · 링크 : URL 형식(http(s)://), 종료일 < 시작일, 필수값 누락
            · 수익 : 연월 형식(YYYY-MM), 금액이 0 이상 정수
        - 오류 행이 있으면 '오류 행은 건너뛰고 정상 행만 등록' 확인 체크박스가 뜨며,
          체크해야만 실행할 수 있습니다.
        - 수익 업로드에서 같은 (인플루언서, 연월) 조합이 파일 안에 중복되면 경고하고
          '마지막 행 값만 등록' 여부를 확인합니다. (기본 체크)
        - 실행은 행마다 linkCreate / revenueUpsert 를 **순차 호출**하며 진행률(N / M)을 표시합니다.
          중간에 실패해도 나머지 행은 계속 진행하고, 완료 후 성공/실패 건수와
          실패 사유 목록을 보여준 뒤 목록을 자동 새로고침합니다.
        - ⚠ Apps Script 왕복이 **건당 2~4초**입니다. 100건이면 3~7분 정도 걸립니다.
          진행 중 [중단] 버튼으로 언제든 멈출 수 있고, 이미 등록된 건은 유지됩니다.
          업로드가 끝날 때까지 창을 닫거나 새로고침하지 마세요.
   8-4) 보안
        - 업로드 파일명·셀 값은 신뢰하지 않습니다. 화면 표기는 전부 textContent 로만 합니다.
        - 엑셀로 내보내는 문자열 셀이 '=' '+' '-' '@' (또는 탭·개행)으로 시작하면
          앞에 작은따옴표(')를 붙여 저장합니다. (수식 인젝션 방지)

9) 링크 추가 모달 — 인플루언서 텍스트 검색
   - 기존 셀렉트 박스를 **텍스트 입력 + 실시간 자동완성**으로 교체했습니다.
   - 활동명 / 이름 / 이메일 중 어느 것으로도 검색됩니다. (부분 일치, 대소문자 무시)
     ※ 검색은 원본 값 기준이므로 마스킹 상태에서도 실제 이메일로 찾을 수 있습니다.
       (화면에 보이는 문자열은 항상 마스킹 규칙을 따릅니다)
   - 최대 10건 표시, ↑ ↓ 이동 + Enter 선택, Esc 닫기
   - 선택하면 칩(chip) 형태로 표시되고 ✕ 로 해제합니다.
   - 셀렉트 방식에 익숙한 사용자를 위해 [전체 목록] 버튼으로 전 목록을 펼칠 수 있습니다.
   - 선택하지 않고 저장하면 명확한 오류 안내가 뜨고 검색창에 포커스가 이동합니다.
   - 링크 '수정' 모드에서는 소유자를 바꾸지 않으므로 검색 UI 가 숨겨지고 칩만 표시됩니다.

■ v2.2 변경 사항  ★ 개인정보 관점에서 가장 중요

10) 회원 기본키(PK)가 UUID → **이메일** 로 교체되었습니다.
    - `record.id` / `link.memberId` / `revenue.memberId` 값이 **이메일 원문**입니다.
      그대로 화면에 찍으면 마스킹이 통째로 우회되므로,
      서버가 함께 내려주는 **`memberIdMasked`**(`ho***@example.com`)를 씁니다.
    - 규칙은 단 하나입니다.
        · 화면·엑셀 표시 → `disp.memberId(id, memberIdMasked)`
          (마스킹 ON → memberIdMasked / OFF → 원본)
        · 서버로 보내는 payload → **언제나 원본 id**
      두 값을 함께 내려주는 이유가 그것입니다. (마스킹 우회 방지 + 조작 가능성 유지)
    - 서버가 `memberIdMasked` 를 주지 않는 경우(구버전 배포 등)에도
      클라이언트가 직접 마스킹합니다. (이메일 → `ho***@도메인` / 그 외 → 앞 8자)
    - ★ 이 폴백 규칙은 서버 `maskId()` 와 **문자 단위로 동일**해야 합니다.
      별표는 아이디 길이와 무관하게 **항상 3개 고정** 입니다.
        · 규칙이 갈라지면 서버가 준 값과 폴백이 한 화면 안에서 서로 다른 모습이 됩니다.
          (회원ID 변경 확인 모달의 "현재 회원ID … → 변경 후 …" 한 줄에서 바로 드러납니다)
        · 별표를 길이에 비례시키면 마스킹본만 보고도 아이디 길이를 알 수 있습니다.
      → 5차 QA 에서 서버 규칙으로 통일했고, 하네스 admin-pii.js P-0 이
        서버 실물 함수와 ADMIN 실물 함수를 직접 맞대어 검사합니다.
    - 마스킹 규칙이 적용된 지점
        · 신청 내역 상세 모달의 [회원ID: …] 메타 표기
        · 링크 관리 / 수익 관리의 인플루언서 표기 (목록에 없는 회원 포함)
        · 링크 추가 모달의 인플루언서 칩 · 자동완성 목록
        · 엑셀 조회결과 다운로드 3종(신청내역 / 링크관리 / 수익관리)의 **[회원ID] 컬럼 신설**
        · 엑셀 대량 업로드 미리보기의 이메일 열과 오류 사유
    - ⚠️ 예외 2곳 (의도된 설계 — SPEC §4-0)
        · 양식(인플루언서목록) 시트 : 이메일이 **업로드 식별키**라 원본이 필요합니다.
          → 마스킹 ON/OFF 와 무관하게 **항상 확인 모달**을 거치며,
            마스킹 ON 일 때는 "마스킹 중이지만 이 양식만은 원본이 들어간다" 고 명시 경고합니다.
        · 상세 모달의 [이메일] 입력란 : 편집용 폼 필드입니다.
          (마스킹본을 넣으면 저장 시 데이터가 손상되므로 원본을 유지합니다)
    - `id` 를 UUID 로 가정하는 코드(정규식 검증 · 길이 가정 · 앞자리 자르기)는 없습니다.

11) 이메일을 수정하면 **회원ID 자체가 바뀝니다.**
    - 상세 모달에서 이메일을 바꿔 [저장] 하면 먼저 확인 모달이 뜹니다.
        "회원ID가 변경됩니다. 연결된 링크·수익 데이터도 함께 갱신됩니다."
    - 저장 후에는 `update` 응답의 **새 id** 로 로컬 상태를 교체하고 **목록을 재조회**합니다.
      선택 체크 상태 · 링크 필터 · 링크/수익 뷰 캐시도 함께 새 id 로 옮깁니다.
      (교체하지 않으면 이후 링크 추가 / 수익 저장 / 삭제가 '대상을 찾을 수 없습니다' 가 됩니다)
    - 서버가 `code:'CASCADE_FAILED'` 를 반환하면 전용 경고 모달을 띄웁니다.
        "데이터가 불완전할 수 있습니다 — 재시도하지 마시고 담당자에게 확인을 요청하세요."
    - `EMAIL_REQUIRED` / `INVALID_EMAIL` 오류 코드별 안내 문구를 추가했습니다.

12) 수익 관리 [변경분 일괄 저장] 버튼 재배치
    - 위치 : 상단 조회 툴바 → **[월별 수익 입력] 영역의 우측 상단** (제목과 같은 줄, 오른쪽 정렬)
    - 헤더 영역은 `position: sticky; top: 64px` 이라 그리드를 스크롤해도 버튼이 계속 보입니다.
      (데스크톱 기준. 상단 바 높이 64px 아래에 붙습니다)
    - 활성 조건
        · 변경된 행이 없으면 **비활성 + "변경사항 없음"**
        · 변경된 행이 있으면 **활성 + "💾 변경분 일괄 저장 (N건)"** 으로 건수를 표시
    - 진행률(N / M) 표시는 버튼 왼쪽에서 기존과 동일하게 동작합니다.

■ 실행 환경 (중요)

- 비밀번호 변경 기능은 WebCrypto(crypto.subtle)를 사용하므로
  보안 컨텍스트(HTTPS 또는 http://localhost)에서만 동작합니다.
  admin.html 을 file:// 로 직접 열면 비밀번호 변경만 비활성화됩니다.
  (그 외 기능은 정상 동작)
- 로컬 확인 방법 : 이 폴더에서
      python -m http.server 8000
  실행 후 브라우저에서 http://localhost:8000/admin.html 접속
- 엑셀 기능은 SheetJS(CDN)를 사용합니다. 인터넷(또는 CDN 허용)이 필요하며,
  로드에 실패하면 엑셀 버튼만 비활성화되고 나머지 기능은 모두 정상 동작합니다.
  ※ 헤더 셀의 굵게·배경색은 SheetJS 배포본에 따라 적용되지 않을 수 있습니다.
    열 너비 / 틀 고정 / 자동 필터는 정상 적용됩니다.
- 서버 URL은 admin.js 의 CONFIG.APPS_SCRIPT_URL 한 곳에서만 관리합니다.
  (auth.js 의 CFG.apiUrl 과 동일한 값이어야 합니다)

■ 참고
────────────────────────────────────────────────
- ADMIN은 데스크톱 기준 화면입니다. (모바일 최적화 대상 아님)
  1280px 이하에서는 테이블이 가로 스크롤로 표시되며 레이아웃은 깨지지 않습니다.
  엑셀 업로드 미리보기 모달도 가로 스크롤로 대응합니다.
- 개인정보(이름·이메일·휴대폰·**회원ID**)는 기본 마스킹 상태이며,
  링크 관리·수익 관리 화면의 인플루언서 표기와 엑셀 다운로드에도 동일한 마스킹 규칙이 적용됩니다.
- 모든 조회·수정·삭제 이력은 서버의 '접근로그' 시트에 기록됩니다.
- 상세 규격은 공용_서버_문서/SPEC.md (§1-7, §3-2, §4-0, §4-4, §5, §6) 를 참고하세요.
- 회원ID 마스킹 / 회원ID 변경 / 수익 저장 버튼은
  공용_서버_문서/_테스트하네스/admin-pii.js 가 admin.html·admin.js 를 실제로 실행해 검증합니다.
    node admin-pii.js
- 엑셀 대량 업로드가 호출하는 서버 API
    링크 : linkCreate  { memberId, name, url, startAt, endAt, memo }
    수익 : revenueUpsert { memberId, ym, amount }   (기존 값이 있으면 갱신)
